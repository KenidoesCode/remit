I
Act I · the neighbourhood

Say one sentence. The agent does the rest — inside a line you drew.

The catalog is the neighbourhood. The payment is across town. What you authorised is a thread anchored to something that does not move, and the agent may wander anywhere on this side of it without asking.

›
II
Act II · the agent moves

It searches, compares, picks — and then the merchant gets a turn.

Ranking is deterministic; the model never scores a product. The revenue engine proposes accessories with a reason and an exact marginal cost. Nothing is added silently, and offers are accepted against a running total, so three that each fit cannot jointly break the envelope.

III
Act III · the line

Take the human's authority. Move it. Watch the system re-decide.

Same basket, different permission. Every drag re-runs the real policy engine — no model call, no payment, no writes — and reports how long the pure function actually took.

IV
Act IV · break it

Go on. Try.

Every lever below is wired to a real code path. Move the price after selection, delist the product mid-journey, revoke the authority, forge a webhook. REMIT names the clause that caught it.

and the same journey with the boundary switched off

Not a different build — the identical code path with a permissive policy file. Same user, same merchant, same agent, one line of data changed.
