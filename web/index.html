01 · live commerce — the agent moves

It searches, compares, picks — and then the merchant gets a turn.

Ranking is deterministic; the model never scores a product. The revenue engine proposes accessories with a reason and an exact marginal cost. Nothing is added silently, and offers are accepted against a running total, so three that each fit cannot jointly break the envelope.

01 · the approval walk-through

What an approval is worth, in five presses.

A step-up that returns true from a checkbox is not an approval — it is a boolean, and a boolean cannot answer the only question a dispute asks: approved what? Every press below is a real request to the running engine. Each one states what it expects before it fires, and then shows what actually came back.

02
02 · REMIT arena

Seven agents. One world. The one that earns most does not win.

Every agent gets the same merchant, the same catalog, the same prices and the same 540 sentences. Only the policy data differs — and the boundary itself is one key in that data, so all seven execute the same code in the same order. The score is economic value × trust², and money moved outside the mandate is subtracted rather than counted. An agent that spent what nobody authorised cannot place first, however much it made.

What would have happened if REMIT had not been there?

The same sentence, run twice in this same process. "Without" is not a different build and not a mock — it is the identical journey under a policy file with integrity_layer set to false. One key. Type anything; both worlds run on the test-mode gateway and no money moves in either.

05 · break REMIT

Go on. Try.

Every lever below is wired to a real code path. Move the price after selection, delist the product mid-journey, revoke the authority, forge a webhook. REMIT names the clause that caught it.

the self-destruction lab

Twenty-three attacks REMIT runs against itself, across the three surfaces an agentic commerce system actually exposes. Each one names the invariant it is trying to break before it runs, and fires live against a throwaway instance when you press it. One of them is expected to succeed — the list says which, and why.

06
06 · evaluation lab

260 explicit cases, thirteen categories, and one invariant over all of them.

Each case asserts a property, not an expected product — pinning a SKU would make this a change-detector. The universal invariant is the one that matters: whatever happens, if money moved on AUTO it moved inside the line that was stated. The matrix caught a real bug on its first run, and that bug is written up in room 08.

07 · audit trail

Every decision this instance has taken, in order, hash-chained.

A single writer proves ordering, not honesty — so this is tamper-evident, not tamper-proof, and the difference is stated rather than glossed. Each link carries the previous hash; break one and every link after it stops verifying.
