SDK
build with remit

REMIT is infrastructure, so it installs like infrastructure.

The SDK is the same /v1 protocol an external agent talks to, with types on it. No second engine, no second authorization check.

$ npm install remit-sdk
$ npm i -g remit-sdk the remit CLI 
import { Remit } from "remit-sdk";

const remit = new Remit({ baseUrl });

// the human's words become a bounded authority
const { intent } = await remit.intents.create({
  text: "buy a laptop under 50000"
});

// ask before doing. no money moves.
const d = await remit.authorization.evaluate({
  text: intent.utterance
});

d.verdict;  // "STEP_UP"
d.failed;   // ["MATCH-001"]

01 · live commerce — the agent moves

It searches, compares, picks — and then the merchant gets a turn.

Ranking is deterministic — the model never scores a product. Offers are accepted against a running total, so three that each fit cannot jointly break the envelope.

What an approval is worth, in five presses.

02 · REMIT arena

Seven agents. One world. The one that earns most does not win.

Same merchant, same catalog, same 540 sentences; only the policy data differs, and the boundary is one key in it. Money moved outside the mandate is subtracted — so the biggest earner cannot place first.

04 · a limit is not an authority

Every row below is under the number the human said. Only two are what they asked for.

A spending limit can ask one question: how much. It cannot ask what. Nothing here is scripted — if REMIT starts allowing the laptop stand, this table will say so.

05 · break REMIT

Go on. Try.

Every lever is wired to a real code path. Move the price after selection, delist mid-journey, revoke the authority, forge a webhook. REMIT names the clause that caught it.

the self-destruction lab

Twenty-three attacks REMIT runs against itself, live, on a throwaway instance. Each names the invariant it is trying to break. One is expected to succeed — the list says which, and why.

06 · evaluation lab

260 explicit cases, thirteen categories, and one invariant over all of them.

Each case asserts a property, not an expected product — pinning a SKU would make this a change-detector. The invariant: if money moved on AUTO, it moved inside the line that was stated.

Every decision this instance has taken, in order, hash-chained.
